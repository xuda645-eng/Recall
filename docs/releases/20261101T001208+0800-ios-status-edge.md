## Corrected Diagnosis

The initial approach removed decorative soft shadows. The user corrected that
interpretation and supplied a physical iPhone screenshot showing a progressive
blur over the Logo's upper edge, not merely a shadow outside it. Shadow-only
changes and their assertions were withdrawn before any commit or deployment.
The original visual shadows are retained in the final implementation.

The existing opaque header and independent body scroller do not themselves
prove that an installed iPhone has no system-owned scroll-edge effect. WebKit's
native layer hides the top effect when a visible fixed color extension exists;
it determines this from an eligible edge element and the host's obscured insets.
There is no public CSS/manifest switch used by this change.

Sources inspected during this task:

- [WebKit native fixed color extension and scroll-edge visibility](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebView.mm).

These support a targeted compatibility workaround, not proof that the user's

  `document.body`, outside every moving foreground/drawer ancestor. Detect
  standalone display mode or Safari's standalone flag; release the mode-change
  listener and portal on unmount.

- `memory-appearance.css`: only in WebKit and mobile standalone mode, make the
  sample full-width, fixed at top zero, 11px high, above page content, with solid
  theme-matched background color. Empty `background-clip: text` means nothing is
  painted; `pointer-events: none` prevents tap interception. 11px exceeds the
