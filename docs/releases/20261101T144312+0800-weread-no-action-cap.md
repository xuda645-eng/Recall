## Changes And Preserved Boundaries

- Removed the job-creation and persisted-job validation 20-question ceiling.
  Removed the online confirmation button's 20-question disable condition.
  Online highlights remain selected by default; users can still deselect any.
- Removed manual AI generation's `slice(0, 20)`: the serial loop now handles all
  selected eligible highlights, preserving existing/generated/manual questions.
- Both interfaces explain the daily 300-model-attempt and hourly 120-request
  protections instead of promising batches of 20 or the obsolete daily 100.
  Manual generation now checks the same daily-budget preflight and handles its
  failure before sending any originals, consistent with the automatic path.
- No separate per-action AI question ceiling is substituted. Existing import
  safety capacity remains five online books, 1000 highlights and 5MiB; a single
  model original still must be no more than 6000 characters. Server output stays
  capped at 384 tokens. These are independent of the removed 20-question gate.
- Daily budget remains 300, shared by personal-space devices, with failed model
  attempts counted and usage retained. The same UTC reset remains 08:00 China.
  The conservative preflight still rejects a pending scope larger than the
  remaining daily budget before sending originals. It is not a reservation;
  another device can consume budget and cached results may need no model call.
- Hourly 120 requests still applies, including cache hits. If a large job hits
  this limit or a model/network error, it stops with successful questions kept.
  Explicit retry after the window resets continues pending questions. No timed
  background retries, paid budget test, automatic resume or counter reset.
- Automatic jobs retain seven-day IndexedDB drafts, safe cross-tab lock,
  pause/refresh recovery, changed-card consent and atomic all-success import.
  An incomplete batch is not written. Manual drafts remain current-page only
  and still require a separate explicit import confirmation.
- No backend/schema/production-binding/credential changes, no real library
  writes, no full-book source acquisition and no image-viewer implementation.
