## Cause And Evidence

The user reported repeated native macOS dialogs for "Playwright" and
"Google Chrome for Testing". These are the WebKit and Chromium test hosts,
not dialogs produced by Recall. Local macOS `15.6.1`, Apple Silicon reports
identify `node` as the parent and `ChatGPT` as the responsible app in the
`com.openai.codex` coalition. During `23:34:52` to `23:35:05+08:00`, browsers
repeatedly exited with `EXC_CRASH / SIGABRT` at `_RegisterApplication`:

- Chromium: `abort -> _RegisterApplication -> TransformProcessType`.
- WebKit: `abort -> _RegisterApplication -> GetCurrentProcess`, then AppKit
  menu-bar initialization frames.

The restricted shell reported `CODEX_SANDBOX=seatbelt`. An approved
`exec_command` process reported no sandbox marker and successfully ran the
same installed Chromium `1223` and WebKit `2272` binaries. This supports a
sandbox/GUI-registration launch failure, not broken Recall page code or a
need to reinstall the normal user's browser. Headless mode does not avoid
this macOS initialization. Continuing through test workers launches another
browser and creates another report; ignoring one dialog cannot stop that.

Only the minimal diagnostic facts above are published. Raw reports, process
inventories, user identifiers and private screenshots remain outside Git.
Other apps' MCP processes were not stopped or reconfigured.

## Changes

- `scripts/browser-runtime.mjs` rejects the observed macOS Seatbelt environment
  before browser launch with `RECALL_BROWSER_SANDBOX` and an explicit instruction
  to rerun the same command via the approval-controlled escalated tool or a
  normal Terminal. It does not remove sandbox markers or suppress OS reporting.
- `scripts/run-playwright.mjs` protects `test:e2e` and `test:e2e:cloud`, including
  custom prototype configs passed through those scripts.
- Root, cloud and synthetic WeRead Playwright configs have their own early
  guard, protecting direct CLI invocations as well. Their shared global setup
  checks one startup/mobile context/blank page per selected project before
  workers. Any startup/render failure stops the suite without automatic retry.
- Existing mobile/screenshot scripts guard direct browser launch. Tests cover
  those real entries, both normal and unsafe environments, startup failure,
  rendering failure, cleanup and no later-engine retry.
- App `AGENTS.md` and `docs/PWA.md` require future prototype/ad hoc browser
  scripts to use the same guard and approved execution path. The parent
  workspace `AGENTS.md` is a local-only mirror, not committed with app source.
- This guard covers Recall's maintained entry points, not every unrelated
  app or arbitrary external `node_repl` script. New independent prototype
  configs must use the guarded launcher/shared setup. The concurrent prototype
  task and its untracked files are preserved, not bundled into this task.

### Recovery And Limits

- Initial `pnpm exec vitest ...` / `pnpm exec eslint ...` failed because the
  supplied pnpm fallback attempted dependency installation then aborted
  removal of the modules directory with
  `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`. No purge/reinstallation was
  forced. Existing local Node entry points successfully ran the same tools.
- First approved E2E attempt failed before browser preflight:
  `Process from config.webServer was not able to start. Exit code: 1`.
  Its existing build/preview command uses pnpm, but the underlying webServer
  stderr was not retained, so its exact failure cause is not independently
  proven. Recovery built and served the same production app
  through existing Vite Node entry points; the unchanged local URL was reused
  by the original E2E config. This is not a waived mobile check.
- The first focused test run failed on `import.meta.url` in the default
  happy-dom environment. The tooling test explicitly uses Vitest's Node
  environment; all 17 tests then passed. The explicit tooling type-check
  initially required TypeScript 6's `--ignoreConfig`; the corrected command
  passed.
- Reading processes was initially denied by the shell sandbox; read-only
  inspection was retried through the tool's approval mechanism.
- Native `cua.getApp('Problem Reporter')` inspection timed out. No UI dismissal
  was performed or claimed. Already queued old dialogs may still need to be
  ignored; do not click "Reopen" to restart a crashed test host.
- Browser simulation is not physical iPhone 15/Safari home-screen acceptance.
  No new physical-device acceptance claim is made. No OS setting, crash
  reporter, browser security configuration or user's normal Chrome was changed.
- Required Windows vault files and Graphify were unavailable; the existing
  handoff/architecture map and targeted tooling inspections were used.
